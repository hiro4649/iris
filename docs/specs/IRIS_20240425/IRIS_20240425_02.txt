# IRIS 開発仕様書

## Phase02 完全整合版（最終整合版・単体完結版）

低遅延リアルタイム反応フェーズ

---

## 00. 文書の役割

本仕様書は、**Phase00 完全拘束版（最終整合版）を唯一の上位拘束**とし、さらに **Phase01 完全整合版（最終整合版）** が producer する canonical export を唯一の入力 source として、IRIS が **低遅延で自然な反応候補を返すための最小実装仕様** を定義する。

本書は Phase00 と衝突してはならない。
本書は Addendum を前提にしない。
本書は旧版 Phase02 より優先される。
本書に未定義の挙動は実装禁止とする。

このフェーズで作るものは以下だけである。

Event / Intent に対する反応候補の選択
反応の微小変化
最小表情・最小挙動の付与
同じ反応の連打抑制
高負荷時の劣化運転
deterministic な fallback
Phase03 / Phase04 に渡す canonical reaction export

このフェーズでは LLM を使わない。
このフェーズでは長文生成をしない。
このフェーズでは長期記憶更新をしない。
このフェーズでは relationship を更新しない。
このフェーズでは action_type を決定しない。
このフェーズでは world_command を生成しない。
このフェーズの役割は、**IRIS を賢くすることではなく、速く壊れずに生きて見せること**である。

---

## 01. 目的

Phase02 の目的は以下である。

Phase01 の intent export を 150ms 未満で反応候補へ変換すること
反応を deterministic に選べること
同じ意味の中で表現差分を持てること
反応の単調化を抑えること
高負荷時もキャラクター基調を維持すること
Phase03 / Phase04 に渡す canonical reaction export を固定すること
reaction-level で止め、action 決定を Phase04 に委譲すること

review path 処理

## 03. 完成定義

以下をすべて満たした場合のみ、Phase02 完了とみなす。

p95 応答時間が 150ms 未満であること
p99 応答時間が 180ms 未満であること
1000 イベント連続処理で停止が 0 件であること
LLM 呼び出し回数が 0 件であること
同一入力に対して同一 reaction_id が再現されること
同一 reaction_id の連続出力が禁止条件どおりに抑制されること
同一 variation_group の 3 連続出力が 0 件であること
fallback が常に測定可能であること
high load 時も tone と character_tag 欠落が 0 件であること
Consistency Guard fail 時にも無反応が 0 件であること
Phase02 Export が Phase00 の Phase02→Phase03 / Phase04 I/O 契約を満たすこと
Phase02 停止時も Phase01 Export 経路が壊れないこと
Phase02 Export に action_type が含まれないこと
Phase02 Export に raw payload 全文が混入しないこと

## 04. 全体構造

Phase02 の固定パイプラインは以下とする。

```text
Phase01 Export
-> Reaction Classifier
-> Reaction Selector
-> Variation Selector
-> Micro Expression
-> Consistency Guard
-> Repetition Guard
-> Fallback Resolver
-> Phase02 Export Builder
-> Output
```

この順序以外は禁止する。
ステップ統合は禁止する。
Selector が Variation を兼務してはならない。
Consistency Guard は最終候補決定の直前に必ず通す。
world_command 変換は禁止する。
Adapter へ判断を逃がすことは禁止する。
Phase02 は Planner ではない。
Phase02 は Action 決定層ではない。
ここで決めるのは **reaction / tone / emotion / character_tag / variation** までである。

Phase02 は action_type を決定してはならない
Phase02 は skill_id を決定してはならない
Phase02 は world_command を生成してはならない
trace_id は end-to-end で必須である
Phase02 は review queue を受け取ってはならない
Phase02 は Phase01 intent を上書きしてはならない

## 06. 入力契約

Phase02 は **Phase01 Export 契約** に一致する入力だけを受け取る。
required は以下とする。

```json
{
  "trace_id": "uuid",
  "event_id": "uuid",
  "source": "youtube|minecraft|vrchat|system",
  "intent": "greet|respond|observe|ignore",
  "target_presence_id": "uuid",
```

target_presence_id は null であってはならない
Phase01 由来でない暗黙入力を受け取ってはならない
raw payload 全文を参照してはならない
linked_identity_id を暗黙参照してはならない
review path 由来 field を受け取ってはならない

tone

```text

```

emotion

```text
neutral

awkward
```

character_tag

```text
soft

```

intent

```text

```

新しい tone / emotion / character_tag の導入は禁止する。

tone と character_tag の推奨対応は以下に固定する。

```text

calm -> calm
```

`tease` は character_tag としてのみ使用し、tone に追加してはならない。

## 08. Reaction Bank

Phase02 は固定 Reaction Bank を持つ。
runtime 中の書き換えは禁止する。
Reaction Bank は rule-based selection 用の静的データである。

最小構造は以下とする。

```json
{
  "reaction_id": "string",
  "intent": "greet|respond|observe|ignore",
  "tone": "friendly|playful|excited|calm",
  "emotion": "neutral|happy|surprise|awkward",
  "character_tag": "soft|playful|tease|hype|calm",
  "variation_group": "string",
  "micro_expression_set": ["string"],
  "cooldown_ms": 0,
  "priority": 0,
  "enabled": true
}
```

最低限、intent ごとに 2 件以上の reaction を持つこと。
ただし意味を変えない範囲で差分を作ること。
Reaction Bank に world 固有 API 名を入れてはならない。
Reaction Bank に action_type を持たせてはならない。
Reaction Bank に skill_id を持たせてはならない。
Reaction Bank に raw text 長文を保持してはならない。

---

## 09. Reaction Classifier

Reaction Classifier は Phase01 の intent を受けて、Reaction Bank から候補集合を絞る。
この時点では最終選択をしない。

責務は以下とする。

intent に対応する候補群の抽出
disabled reaction の除外
target_presence_id 欠損候補の除外
cooldown 対象候補の除外
speaker_token と mention_flag を補助信号として候補優先度へ反映

禁止事項は以下とする。

Variation 選択
tone 変更
emotion 創出
character_tag 創出
memory 更新
world 依存補正
action_type 決定

Classifier は候補集合を狭めるだけである。
意味を変えてはならない。

---

## 10. Reaction Selector

Reaction Selector は候補群から 1 件を deterministic に選ぶ。
ランダムは禁止する。

選択に使用してよい要素は以下とする。

intent
source
mention_flag
priority
speaker_token
reaction priority
cooldown 状態
直近 reaction_id 履歴

選択規則は以下を推奨する。

高 priority

> mention_flag=true
> speaker_token=true
> cooldown 未該当
> reaction priority 高
> 直近重複の少ない候補
> reaction_id の辞書順固定

同一入力に対して異なる reaction_id を返してはならない。
selector が variation を兼務してはならない。
selector が fallback を兼務してはならない。

---

## 11. Variation Selector

Variation Selector は、選ばれた reaction_id に対して意味を変えない微小差分を選ぶ層である。
ここで別の反応意味へ飛んではならない。

最小構造は以下とする。

```json
{
  "variation_id": "string",
  "reaction_id": "string",
  "variation_group": "string",
  "tone": "friendly|playful|excited|calm",
  "emotion": "neutral|happy|surprise|awkward",
  "character_tag": "soft|playful|tease|hype|calm",
  "micro_expression_hint": "string|null",
  "enabled": true
}
```

Variation Selector の責務は以下のみ。

同一 reaction_id 内で variation を 1 件選ぶ
variation_group の連打を抑える
tone / emotion / character_tag を canonical set 内で保持する

禁止事項は以下とする。

intent 変更
reaction_id 意味変更
action_type 決定
world_command 生成
random selection

Variation は表現差分であって、行動決定ではない。

---

## 12. Micro Expression

Micro Expression は最小表情・最小挙動ヒントの付与だけを行う。
行動を決めてはならない。
world ごとの実行詳細を決めてはならない。

最小出力は以下とする。

```json
{
  "micro_expression": "smile_small|blink_once|tilt_head|pause_short|none"
}
```

新しい micro_expression を増やす場合は固定辞書に追加し、自由生成してはならない。
high load 時は `none` を許可する。
tone と character_tag が落ちているのに micro_expression だけ残すような逆転は禁止する。

---

## 13. Consistency Guard

Consistency Guard は、選択された reaction / variation / tone / emotion / character_tag の組み合わせが、Phase02 の canonical 制約に一致しているかを検証する。
人格判断をする層ではない。
長期記憶を見る層でもない。

最低限の検証項目は以下とする。

intent と reaction_id の整合
reaction_id と variation_id の整合
tone と character_tag の対応整合
canonical enum 外値の排除
blocked / invalid target の排除
trace_id / event_id の維持

Guard fail 時は以下を許可する。

variation の差し替え
reaction の差し替え
fallback への送出

Guard fail 時に無反応で落としてはならない。
Guard が action_type を補うことは禁止する。

---

## 14. Repetition Guard

Repetition Guard は単調化抑制専用である。
人格判断をしてはならない。
意味変更をしてはならない。

最低限のルールは以下とする。

同一 reaction_id の連続出力禁止
同一 variation_group の 3 連続出力禁止
同一 tone の過度な連打を警告
直近 5 件中の重複率を測定

この Guard は reject よりも置換を優先する。
置換不能時のみ fallback に送る。
置換によって intent を変えてはならない。
置換によって character_tag を canonical 外へ飛ばしてはならない。

---

## 15. Fallback Resolver

Fallback Resolver は以下の場合に発火する。

candidate 不在
Guard fail
cooldown 衝突
variation 不在
high load
unknown internal error

fallback は無反応にしてはならない。
最低限以下を返すこと。

intent が `greet|respond` の場合は安全反応候補 `safe_speak_like`
intent が `observe` の場合は `observe_minimal`
intent が `ignore` の場合は `wait_minimal`

ただし fallback でも **action_type は決めてはならない。**
fallback で返すのはあくまで reaction-level 候補である。

fallback でも tone と character_tag を欠落させてはならない。
空出力は禁止する。
world_command を返してはならない。
skill_id を返してはならない。

---

## 16. High Load 時の劣化運転

Phase02 は high load 時に劣化運転できなければならない。
ただしキャラクター基調は落としてはならない。

high load 時の処理は以下とする。

Variation Selector を簡略化
Micro Expression を `none` または最小集合へ制限
Repetition Guard の履歴窓を縮小
Fallback を優先
Reaction Bank の検索範囲を intent 単位の最小候補集合へ絞る

禁止事項は以下とする。

tone を削る
character_tag を削る
blocked presence へ出力する
ignore へ強制落下させ続ける
action 決定を前倒しする
Reaction Bank を runtime 更新する

## 26. 実装順序

Phase02 は以下の順で実装すること。

Reaction Bank を固定する
Reaction Classifier を作る
Reaction Selector を作る
Variation Selector を作る
Micro Expression を作る
Consistency Guard を作る
Repetition Guard を作る
Fallback Resolver を作る
Phase02 Export Builder を作る
ログを入れる
unit test を入れる
integration test を入れる
CI fail ルールを入れる

この順序を崩すな。
特に先に賢い会話戦略を入れるな。
先に world ごとの反応差分を入れるな。

## 28. 開発者向け最終指示

Phase02 の目的は、IRIS を賢く見せることではない。
**IRIS を即座に反応している存在に見せること**だ。

ここでやるべきことは少ない。
だが、その少ないことを厳密にやらないと、後続全部が壊れる。

ここで action を決め始めるな。
それは Phase04 の仕事だ。
ここで world に最適化するな。
それは Adapter の仕事だ。
ここで memory を触るな。
それは後段の仕事だ。
ここで raw payload を持ち続けるな。
それは deterministic 性を壊す。
ここで random に逃げるな。
再現性が死ぬ。

Phase02 は高速で、固定的で、軽く、壊れず、同じ入力に同じ反応候補を返すことだけを優先して実装すること。
**速さと境界を守れ。賢さはまだいらない。**
